# ADR-002: Use Synthetic Banking Event Generation

## Status

Accepted

---

## Context

The Enterprise Banking Data Platform requires a continuous source of banking events to demonstrate ingestion, transformation, historical modeling, and analytical processing.

During the design phase, we considered whether the platform should rely on publicly available banking datasets or generate synthetic banking events internally.

The objective was to build a repeatable, extensible, and legally unrestricted data source capable of supporting streaming workloads and future platform enhancements.

---

## Decision

The platform will use an internal event generation engine to produce synthetic banking events instead of relying on external datasets.

The generator will produce the core business entities used throughout the platform:

* Customers
* Accounts
* Merchants
* Transactions

The generated events will be exported in NDJSON format and serve as the operational source system for the remainder of the platform.

---

## Rationale

Synthetic data generation provides complete control over the structure, volume, and quality of the generated data.

Unlike static public datasets, an internal generator allows the platform to:

* Produce unlimited banking events.
* Simulate real-time transaction streams.
* Control event frequency.
* Introduce realistic data quality issues.
* Generate historical data on demand.
* Extend the data model without replacing the source dataset.

This approach creates a repeatable development environment while avoiding licensing, privacy, and compliance concerns associated with production banking data.

---

## Alternatives Considered

### Option 1 — Public Banking Dataset

Examples include Kaggle banking datasets and other publicly available financial datasets.

**Advantages**

* No implementation effort.
* Realistic historical records.

**Disadvantages**

* Static data.
* Limited scalability.
* Cannot simulate streaming events.
* Difficult to extend.
* Often contains licensing or privacy restrictions.

---

### Option 2 — Synthetic Banking Event Generator (Selected)

The platform generates banking events internally using Python and Faker.

**Advantages**

* Unlimited event generation.
* Full control over the data model.
* Supports streaming simulations.
* Enables realistic testing scenarios.
* Easily extensible as the platform evolves.

**Disadvantages**

* Requires implementation and maintenance.
* Generated data is simulated rather than originating from real banking systems.

---

## Consequences

The event generator becomes the operational source system for the Enterprise Banking Data Platform.

All downstream components—including Snowflake ingestion, the Bronze layer, Silver transformations, Data Vault 2.0, and Gold analytical models—consume events generated by this simulator.

This decision establishes a repeatable and scalable foundation for the entire platform while remaining independent of external datasets.
